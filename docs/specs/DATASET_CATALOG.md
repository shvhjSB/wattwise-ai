# WattWise AI — Dataset Catalog and Training Plan

## Important principle

Do **not** combine every dataset into one training table. They cover different populations, time granularities, units, and objectives. Use one primary dataset for the building-level model, a temporally separated holdout, and supporting datasets only for clearly separate experiments.

## Dataset plan at a glance

| Priority | Dataset | Use in WattWise AI | Required? | Size/notes |
|---|---|---|---|---|
| 1 | Building Data Genome Project 2 (BDG2) | Primary training data for non-residential building/meter forecasting and residual-based anomaly detection | Yes for credible building model; demo mode can run without it | ~53.6 million hourly records; 1,636 buildings, 3,053 meters, 2016–2017 |
| 2 | Local synthetic fixtures generated by the project | Run frontend, API, tests, demo, and controlled injected-anomaly benchmarks | Yes for app reliability; never treat as real-world performance | Keep tiny and generated deterministically |
| 3 | ASHRAE Great Energy Predictor III | Reproducibility / large-scale energy-prediction benchmark and alternate loader | Optional | Roughly 2.6 GB; Kaggle access/competition rules apply. Some data overlap BDG2—do not call it independent external validation without checking overlap |
| 4 | Annotated anomalies from REFIT / REFIT energy data | Separate research experiment on labelled/anomaly-like residential load events and high-resolution appliance signals | Optional advanced extension | Residential domain and different sampling rate; do not mix directly with commercial hourly meters |
| 5 | UCI Appliances Energy Prediction | Small secondary experiment for energy forecasting and weather/indoor sensor feature pipeline | Optional | 19,735 rows, 10-minute readings over ~4.5 months; residential dataset |
| 6 | UCI Individual Household Electric Power Consumption | Small-data regression/data-quality smoke test, or an explicitly separate residential experiment | Optional | 2,075,259 one-minute readings; 2006–2010; missing values present |
| 7 | US EPA eGRID | Optional regional emissions factors for US electricity-related carbon estimates | Optional; only if showing US carbon impact | Official US power-sector emissions/generation dataset. Latest data linked on current page is eGRID 2023 |
| 8 | OpenEI Utility Rate Database (URDB) | Optional real US/international tariff enrichment for cost estimates | Optional | API key required; keep configurable tariff input as the no-key fallback |
| 9 | Open-Meteo Historical Weather API | Optional weather enrichment for user-uploaded datasets with location and timestamp but no weather columns | Optional | Attribution required; free API terms are for non-commercial use, commercial use requires checking/contacting provider |

## 1. Primary: Building Data Genome Project 2 (BDG2)

- Repository: https://github.com/buds-lab/building-data-genome-project-2
- Data description: whole-building non-residential hourly meter readings and metadata/weather, covering 2016 and 2017; approximately 53.6 million measurements across 3,053 meters and 1,636 buildings.
- Layout described by the repository: meter time-series under `data/meters/`, metadata under `data/metadata/`; inspect the actual repository layout and read its README before implementing the parser.
- Official dataset portal metadata: https://openenergyhub.ornl.gov/explore/dataset/the-building-data-genome-2-bdg2-data-set/
- Research paper / dataset citation: Miller et al. (2020), “The Building Data Genome Project 2, energy meter data from the ASHRAE Great Energy Predictor III competition,” Scientific Data 7, 368; DOI: https://doi.org/10.1038/s41597-020-00712-x
- Licence caution: the OpenEnergyDataPortal record lists CC BY 4.0, while the public GitHub repository's `LICENSE` file shows CC BY-SA 4.0. Record the exact source and licence with the downloaded files, prefer the applicable source's terms, and investigate this discrepancy before redistributing adapted data. Do not commit raw data to GitHub.
- Recommended first experiment: choose electric meters only; inspect 10–20 meters first; train with chronological split (earlier months train, later months validate/test); then scale up. Ensure the test window is later than all training rows for those meters. Add a separate building-held-out test for generalization to unseen buildings.

## 2. ASHRAE Great Energy Predictor III

- Competition/data page: https://www.kaggle.com/competitions/ashrae-energy-prediction/data
- Includes meter readings, building metadata, timestamps, and weather tables; large download (~2.6 GB).
- Access requires following Kaggle's account/competition rules. Do not script around sign-in requirements or re-upload the data.
- BDG2 documentation says a subset of BDG2 was used in the ASHRAE competition. Therefore, do not treat ASHRAE as an independent external test set until overlapping buildings/time ranges are checked. It's optional; BDG2 is enough for the first project.

## 3. REFIT and annotated anomalies (advanced optional dataset)

- REFIT official dataset page: https://pureportal.strath.ac.uk/en/datasets/refit-electrical-load-measurements/
- Annotated anomalies resource listing: https://pureportal.strath.ac.uk/en/datasets/refit-electrical-load-measurements/datasets/
- REFIT contains consumption measurements for 20 UK households, aggregate and appliance-level, sampled at 8-second intervals. The official University of Strathclyde page lists CC BY 4.0 for files and provides required citation information.
- Use this only as a separate high-frequency residential experiment or labelled anomaly evaluation. It is not the same domain as commercial building meters; explain this limitation.
- Cite the REFIT publication as requested by the dataset provider and retain attribution/licence information.

## 4. UCI Appliances Energy Prediction (small optional set)

- Dataset page: https://archive.ics.uci.edu/dataset/374/appliances+energy+prediction
- 19,735 instances and 28 features, collected over about 4.5 months at 10-minute intervals in a low-energy building/home; includes indoor temperature/humidity and weather fields.
- Licence: CC BY 4.0; attribute and cite the dataset (Candanedo et al., 2017; DOI https://doi.org/10.24432/C5VC8G).
- Useful for validating feature pipelines or a separate small forecasting notebook, not for direct pooling with BDG2.

## 5. UCI Individual Household Electric Power Consumption (small optional set)

- Dataset page: https://archive.ics.uci.edu/dataset/235/individual+household+electric+power+consumption
- 2,075,259 one-minute observations from one household in France over 47 months (December 2006–November 2010), with nine variables and missing readings.
- Licence: CC BY 4.0. Cite UCI Machine Learning Repository (DOI https://doi.org/10.24432/C58K54).
- Use for data quality tests and a separate household load experiment only.

## 6. Carbon factors: US EPA eGRID (optional)

- Official portal/downloads: https://www.epa.gov/egrid
- eGRID provides US power-sector emissions, generation, emissions rates, and resource mix. The official page currently links to eGRID 2023 data.
- Join using a valid regional/subregion identifier only when its meaning is established. Store the factor year, source, unit, and geography with every calculation. Don't apply a US factor to a non-US building. When no compatible factor is available, show carbon impact as “not configured.”

## 7. Tariffs: OpenEI Utility Rate Database (optional)

- API documentation: https://apps.openei.org/services/doc/rest/util_rates/
- Utility Rate Database offers complex rate structures; API key is required. Tariffs may have time-of-use charges and demand charges, so a single cost/kWh is an approximation, not a complete utility bill.
- MVP fallback: require the user to configure a transparent flat rate (currency + cost per kWh). Only show a cost if a tariff is configured; label flat-rate calculations as estimates. Add time-of-use billing as a separate future module if needed.

## 8. Optional weather enrichment: Open-Meteo Historical Weather API

- API/docs: https://open-meteo.com/en/docs/historical-weather-api
- Historical reanalysis data covers many decades and supports temperature, humidity-related variables, wind, and precipitation.
- The data requires CC BY 4.0 attribution. Free API terms are described as non-commercial use; check current terms before any commercial deployment. BDG2 has accompanying weather data, so this is not required for the primary training pipeline.

## Downloading and data safety

- Keep raw data under `data/raw/` and processed tables under `data/processed/`; both must be gitignored.
- Commit only code, small synthetic fixtures, dataset manifests, and instructions—not entire public datasets.
- Include a CLI such as `python scripts/prepare_bdg2.py --input data/raw/bdg2 --output data/processed/bdg2 --meters electricity --sample-meters 20` (adjust flags to actual implementation).
- The script must first validate paths and required files, print a data-quality summary, preserve timestamps/IDs/units, and fail with actionable messages.
- Generate `data/manifests/datasets.yaml` with source URL, access date, citation, licence URL/status, source checksum where practical, selected files, and preprocessing version.
- Do not report a training score as meaningful until the temporal evaluation, target leakage checks, baseline comparison, and data provenance are documented.
